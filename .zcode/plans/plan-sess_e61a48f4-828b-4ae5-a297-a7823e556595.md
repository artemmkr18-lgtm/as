## Что делаем

Переносим худ из Xyeta (WildClient) в Minar. Рендер всех элементов модуля HUD переписываем 1:1 под Xyeta: те же чипы, скругления, blur-панели, шрифт suisseintlmedium, иконки из wild.png. Старый рендер (Excellent-стиль) удаляем, позиции через HudDrag и автосейв в конфиг остаются как есть.

**Состав (по ответам):** Watermark, Binds, Potions, TargetHUD, Notify-уведомления + кастомный хотбар. Кулдауны, Игрок, Стафф, Информация, Броня — удаляем. В 4-м чипе ватермарки — пинг вместо uid.

## Шаги

### 1. Шрифты и иконки Xyeta
- Копируем `wild.json`/`wild.png` (иконки) и `suisseintlmedium.json`/`.png` из `Xyeta/src/main/resources/assets/wild/fonts/` → `сурсы_фришки/src/main/resources/assets/minar/font/`.
- В `MsdfManager.init()` (ez/minar/utils/render/msdf/MsdfManager.java:21) регистрируем `WILD` и `SUISSE` (+ `ICONS_X` для иконки уведомлений из icons.png, если пригодится). Формат атласов идентичный (mtsdf) — конвертация не нужна.

### 2. Хелперы анимаций
В Xyeta всё живое за счёт EaseBackIn + per-module animation. В Minar есть `Easings` (ez/minar/utils/math/Easings.java) — проверяю наличие OutBack; если нет, добавлю статический `easeBackOut(t, overshoot)` (формула из Xyeta: `1 + c3*(x-1)^3 + c1*(x-1)^2`). Плюс маленький класс-аниматор (напр. `HudAnim`: direction + output, tick по delta) прямо в HUD.java, чтобы повторить поведение `m.getAnimation().getOutput()`.

### 3. Переписываем HUD.java (ez/minar/system/features/render/HUD.java)
Оставляем каркас: `@NewFunction`, HudDrag-позиции (figWatermark, figKeys, figPotions, figTargetHud; лишние удаляем), `onRender2D` с delta/beginFrame/place. Внутри — точный перенос:

- **Watermark** (по WatermarkElement.java): blur 12 + тёмная панель `#7A0A0A0A` (цвет 2048202266) r=8, высота 26; логотип — чип 19x18 с per-corner радиусами (5,5,2,2) в theme-цвете + глиф "A" из wild; 4 чипа (ник/fps/время/пинг) 18px на фоне `-1206577638`, r=3, каждый со своей иконкой (H/I/J/K) в theme-цвете; ширина считается по `Msdf.width(SUISSE, ...)`. Ник — `mc.player.getName()`, время — реальное, пинг — из PlayerListEntry.getLatency().
- **Binds** (по BindsElement.java): фикс ширина 100, заголовок "Binds" + глиф "D", внутренняя чип-панель r=(5,2,2,5) с бордером, строки включённых модулей с биндами: theme-полоска 1x8, имя, бинд по центру правой колонки; offset строки = 13 * animOutput модуля, высота сглаживается `fast(offset+3)`; включение/выключение панели — EaseBackIn 300ms. per-module animation: добавлю в Function (или map в HUD) поле-анимацию, дёргаемую toggle'ом — минимальный вариант: WeakHashMap<Function, HudAnim> в HUD, direction меняется в onEnable/onDisable хуках HUD-события... проще: анимация по факту наличия в кэше строк (как сейчас cachedBinds), но с ease-back. Решение приму при реализации, чтобы не трогать ядро Function.
- **Potions** (по PotionsElement.java): список отдельных чипов 26px с blur, чип-иконка 18x18 (5,5,2,2) + бордер, спрайт эффекта через `drawSpriteStretched` (StatusEffectSpriteManager), имя + "level N" (RomanToArabic — перенесу утилиту, либо заменю на "lvl N" как было — решу по коду, но для 1:1 переносим RomanToArabic), время `StatusEffectUtil.getDurationText`, время-чип в theme-цвете; per-potion EaseBackIn, offset += 28 * output, плавное удаление.
- **TargetHUD** (по TargetHudElement.java): панель 130x50 r=11, аватар-бокс 42x42 (8,8,5,5), аватар скина 32x32 r=6 (TexturePipeline с UV 8/64 как в drawPlayerHead — уже есть), красный тинт при hurt, имя в чипе 76x19.5, сглаженный хп-бар (fast 5.0) + "hp", 4 слота брони 8x8 с бордерами +/items через sizeAnimation(0.38) + alpha-рендер предметов (в Minar вместо ItemRenderUtil.drawItemAlpha — drawItem с матричным scale; alpha через ColorHelper если поддерживается, иначе без alpha). Target: AttackAura.getTarget() → mc.targetedEntity; в chatScreen — свой player как превью (как в Xyeta). LastTarget-механику (удержание после пропажи цели) переносим простой парой полей.
- **Notify** (по NotifyElement.java + NotifyManager): чипы снизу-центр: цветной квадрат 19x18 (5,5,2,2) с иконкой "I" из icons.png, тёмный чип с текстом, y smoothed через fast, анимация EaseBackIn 400ms, fade после 1000ms. Существующий NoticeManager/NoticeItem в Minar заменяем этим — `pushModuleNotification` сохраняем (его зовут из Function.toggle), сигнатура addNotice(title, type) упрощается под один текст ("X был включен").
- **Хотбар** (по InGameHudMixin Xyeta): включаем `shouldDisableDefaultHotbar()` при включённом HUD; в минаровском InGameHudMixin.minar$cancelDefaultHotbar вместо простой отмены делаем cancellable-инъекцию с ПОЛНЫм переносом их renderHotbar: blur-панель 202x26 r=6 снизу-центра, анимированный селектор (fast 10) theme-цвета с per-corner радиусами, слоты 20x20 r=(6/2) с бордером, предметы через sizeAnimation(0.83), offhand-панель 26x26, attack indicator как в ванилле. renderHotbarItem — @Shadow из InGameHud (в Yarn 1.21.11 метод есть; проверю сигнатуру, при отличии — адаптирую).
- **Удаление**: методы renderCooldowns/renderPlayer/renderStaff/renderInfo/renderArmor, их HudDrag'и, related records/кэши, настройки elements сокращаем до: Ватермарка, Кейбинды, Зелья, TargetHUD, Уведомления (+ отдельно хотбар-тоггл "Хотбар" BooleanSetting). Палитру HUD_BG/CHIP_BG заменяем Xyeta-цветами (2048202266, -1206577638, 184549375 и т.д.), getAccent() → ThemeManager.Theme_Color как есть.

### 4. Провайдер иконок для wild-глифов
Малый хелпер (напр. `WildGlyph.draw(matrix, "A", x, y, size, color)`) — обёртка над Msdf.text с font=WILD/SUISSE, чтобы не таскать MsdfFont по коду.

### 5. Сборка и проверка
- `./gradlew build` (по памяти — прямые Gradle-команды, без Python-обёрток).
- Проверка компиляции и маппинга имён (Yarn 1.21.11): drawSpriteStretched, StatusEffectUtil.getDurationText, renderHotbarItem — при отличиях адаптирую.

## Что НЕ трогаем
- HudDrag (позиции/сеттинги/грид) — остаётся, конфиг совместим (удалённые figX-сеттинги просто выпадут из properties).
- ClickGUI, ThemeManager, NotifyManager-интерфейс (pushModuleNotification), остальной клиент.
- Standalone Watermark.java (отдельный модуль) — не трогаем.

## Риски
- Маппинг-отличия 1.21.11 vs Xyeta-версии: решается адаптацией вызовов (все нужные аналоги уже используются в Minar: TexturePipeline, drawSprite нет — добавим через DrawContext.drawTexture/StatusEffectSpriteManager).
- MSDF-атлас wild.png грузится тем же MsdfFont — проверю, что JSON-поля (distanceRangeMiddle отсутствует) читаются (в минаровском loader он опционален судя по формату icons.json — совпадает по структуре).
- Alpha-рендер предметов (ItemRenderUtil.drawItemAlpha) — в Minar нет; сделаю через обычный drawItem (визуально ок) либо матрично, если найдётся alpha-механизм.
